# 1. 情報設計（IA）

## 1.1 基本方針

このシステムの中心オブジェクトは **「動画（Video）」** である。企画・台本・サムネ・投稿・分析といったあらゆる情報は、最終的に1本の動画に紐づく。ナビゲーションは「プラットフォーム別」ではなく「制作ワークフローの進行段階」で組む（＝カンバンの列がそのまま一次ナビゲーションの軸になる）。

もう一つの軸は **「組織（Organization / Workspace）」** である。Phase 1 では WORKAHOLIC 自身が唯一のワークスペースだが、Phase 2 でクライアントごとにワークスペースが増える前提を最初から持たせる。ユーザーはワークスペースに所属し、閲覧できるデータはそのワークスペース内に限定される。

## 1.2 サイトマップ（一次ナビゲーション）

```
[ワークスペース: WORKAHOLIC ▾]

├─ ダッシュボード
├─ コンテンツ管理          … 動画のカンバン/リスト/カレンダー
│   └─ 動画詳細ページ       … 個別動画のハブ画面
├─ アイデア管理            … 企画ネタのストック
├─ 投稿カレンダー          … 全プラットフォーム横断の投稿予定
├─ KPI                    … チャンネル/動画単位の指標
├─ 月次レポート
└─ 設定
    ├─ ワークスペース情報
    ├─ チャンネル連携（YouTube / Instagram / TikTok）
    ├─ メンバー・権限
    ├─ AI設定（ブランドボイス、プロンプトのカスタマイズ）
    └─ （Phase2）クライアント／プラン管理
```

## 1.3 オブジェクトの関係（概念モデル）

```
Organization（ワークスペース）
 ├─ Members（ユーザー×role）
 ├─ Channels（YouTube / Instagram / TikTok / Podcast配信先）
 │
 ├─ Ideas（アイデア）
 │    └─ 採用されると Video を生成（1:1、履歴として残す）
 │
 ├─ Videos（動画＝中心オブジェクト）
 │    ├─ Plan（企画・構成・質問リスト）
 │    ├─ Script（台本、バージョン管理）
 │    ├─ TitleOptions（タイトル案、複数）
 │    ├─ ThumbnailConcepts（サムネ案、複数）
 │    ├─ Description（概要欄・ハッシュタグ）
 │    ├─ EditInstruction（編集指示書）
 │    ├─ ShortsClips（切り抜き案、複数）
 │    ├─ Posts（投稿：プラットフォームごとに複数）
 │    └─ KpiVideoSnapshots（この動画の指標推移）
 │
 ├─ Competitors（競合チャンネル：アイデア提案の入力源）
 ├─ KpiChannelSnapshots（チャンネル全体の指標推移）
 ├─ Inquiries（問い合わせ：動画やキャンペーンと紐づく場合あり）
 ├─ Tasks（今週のタスク／ダッシュボード用）
 ├─ AiGenerations（AIが生成したものすべての履歴・再利用の元）
 └─ Reports（月次レポート）
```

**設計上のポイント**

- Video を中心に据えることで、「動画詳細ページ」を開けば、その動画に関するあらゆる情報（企画〜分析まで）が1画面で完結する。ディレクターの認知負荷を下げる最重要の設計判断。
- AI が生成したコンテンツ（タイトル案・台本・分析など）は上書きせず `AiGenerations` に履歴として保存し、実際に採用されたものだけを本体（`TitleOptions.is_selected` など）に反映する。これにより「AIの提案精度」自体も後から検証・改善できる。
- Idea → Video の変換を1方向のトランジションとして扱う。アイデア段階のリサーチ・企画背景を失わずに動画側へ引き継ぐ。

## 1.4 権限モデル（Phase1でも最初から用意）

| ロール | 想定ユーザー | 権限 |
|---|---|---|
| Owner | 代表・ディレクター本人 | 全権限、請求・設定変更 |
| Director | ディレクター | コンテンツ作成〜最終確認、レポート確定 |
| Editor | 編集担当（外部含む） | 割り当てられた動画の編集指示閲覧、素材アップロード、ステータス更新 |
| Analyst | 分析担当 | KPI閲覧、レポート閲覧、コメント |
| Viewer | クライアント（Phase2で本格利用） | 閲覧のみ（進行状況・レポート） |

Phase1では Owner/Director だけで運用されるが、ロールを最初から分離しておくことで Phase2 のクライアント向け「閲覧用アカウント」がそのまま実現できる。
