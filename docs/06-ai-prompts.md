# 6. AIで生成する投稿文テンプレート

## 6.1 前提：媒体ごとに「別のもの」を書く

同じ内容を使い回すと、どの媒体でも成果が出ません。媒体ごとに読者の状態が違うためです。

| 媒体 | 読者の状態 | 文面の方針 |
|---|---|---|
| YouTube本編 | 検索・関連動画から来る。**能動的** | 検索されるキーワードを含む。概要欄は構造化（要点＋タイムスタンプ＋CTA） |
| YouTube Shorts | スワイプ中。**受動的** | 最初の1行で止める。説明文は短く |
| Instagram Reels | 保存・シェア目的。**受動的だが再訪する** | 1行目にフック、最後に「保存推奨」の文脈。ハッシュタグは中規模タグ中心 |
| TikTok | 完全に受動的。**離脱が速い** | 最短。疑問形か断定形の一文。ハッシュタグは3〜5個 |

`src/ai/prompts/` に媒体別のテンプレートを分けて置く理由がこれです。**ここのチューニングがこの事業のノウハウそのもの**になるので、コードとして残し、改善履歴を追えるようにします。

## 6.2 共通の前提プロンプト（全生成に注入）

```
あなたはWORKAHOLIC株式会社のSNS運用担当です。

【チャンネルの性格】
- 企業の情報発信・採用・ブランディングをテーマにしたビデオポッドキャスト
- 主な視聴者：中小企業の経営者・広報・人事担当（30〜50代）
- 目指すのは「バズ」ではなく「問い合わせにつながる信頼」

【必ず守るトーン】
- 誇張しない。「絶対」「必ず」「たった1つの」等の煽り表現を使わない
- 断定できないことは断定しない
- 専門用語は使ってよいが、初出時は一言で補足する
- 絵文字は媒体ごとの指示に従う（YouTube本編では使わない）

【禁止】
- 事実でない数値・実績の記載
- ゲストが話していない内容の追加
- 他社を貶める表現
```

> この「チャンネルの性格」部分は設定ファイル（`config/brand.yml`）に切り出し、**Phase2でクライアントごとに差し替えるだけで同じシステムが使える**ようにしておきます。

## 6.3 媒体別テンプレート

### ① YouTube 本編タイトル（5案）

```
以下のブリーフから、YouTube動画のタイトル案を5つ作成してください。

【条件】
- 全角28文字以内（スマホ表示で切れないため）
- 検索されうるキーワードを前半に置く
- 5案は必ず異なる切り口にする：
  1案目：課題提起型（「〜で失敗する理由」）
  2案目：具体数値・固有名詞を含む型
  3案目：ゲストの発言を引用した型
  4案目：ノウハウ提示型（「〜する方法」）
  5案目：意外性・逆説型
- 煽り・釣りは禁止。内容と一致していること

【出力形式】JSON配列
[{"title": "...", "type": "課題提起型", "reason": "この案の狙いを1行で"}]

【ブリーフ】
{{brief}}
```

**設計意図**: 「5案出して」だけだと似た案が並びます。切り口を指定することで、選択肢として意味のある5案になります。

### ② YouTube 概要欄

```
以下の構成で概要欄を作成してください。

【構成】
1. 冒頭2〜3行：この動画で何が分かるか（検索結果に表示される部分）
2. 空行
3. ■この動画の要点（箇条書き3〜5点）
4. ■チャプター（brief.mdのショート候補のタイムコードを使用）
5. ■ゲスト紹介
6. ■WORKAHOLICについて＋問い合わせ導線
7. ハッシュタグ3つ（末尾）

【条件】
- 絵文字は使わない
- 全体で800〜1200文字
- 1行あたり全角35文字程度で改行（スマホ可読性）

【ブリーフ】{{brief}}
【確定タイトル】{{title}}
```

### ③ Instagram リール キャプション

```
リール用のキャプションを作成してください。

【条件】
- 1行目：スクロールを止めるフック（20文字以内、句点なし）
- 2行目：空行
- 本文：3〜5行。1行は全角20文字前後で改行
- 最後にCTA：「保存して見返してください」等を文脈に合わせて自然に
- 絵文字は各行末に最大1つまで（多用しない）
- 全体で300文字以内

【ハッシュタグ】本文とは分けて出力
- 10〜15個
- 内訳：大規模タグ（100万投稿超）3つ / 中規模（10〜100万）7つ / 小規模・ニッチ 5つ
- #ワーカホリック #ビジネスポッドキャスト は必ず含む

【出力形式】JSON {"caption": "...", "hashtags": ["...", ...]}

【このショートの内容】{{short_description}}
【元動画のテーマ】{{theme}}
```

**設計意図**: ハッシュタグの規模を混ぜるのは、大規模タグだけだと埋もれ、小規模だけだとリーチが伸びないためです。この配分は運用データが溜まったら見直します。

### ④ TikTok キャプション

```
TikTok用のキャプションを作成してください。

【条件】
- 全角40文字以内。1文で完結させる
- 疑問形（「〜って知ってました?」）か断定形（「〜は逆効果です」）のどちらか
- ハッシュタグは3〜5個。日本語タグ中心
- 絵文字は0〜1個

【出力形式】JSON {"caption": "...", "hashtags": [...]}
【このショートの内容】{{short_description}}
```

### ⑤ サムネイル文言

```
サムネイルに入れる文言を3案作成してください。

【条件】
- 各案とも「大きい文字（最大9文字）」＋「小さい文字（最大14文字）」の2段構成
- 大きい文字だけで意味が伝わること（スマホの小さい表示で読まれるのは大文字だけ）
- タイトルと同じ文言にしない（重複は情報量の無駄）
- 疑問・数字・逆説のいずれかを含める

【出力形式】JSON [{"main": "...", "sub": "...", "note": "狙い"}]
【タイトル】{{title}} 【要点】{{key_points}}
```

### ⑥ 投稿日時案

```
以下の投稿を、指定された投稿スロットに割り当ててください。

【使用可能なスロット】平日 07:00 / 12:00 / 18:00 / 21:00（JST）
【対象読者】中小企業の経営者・広報・人事（30〜50代）

【ルール】
- 本編（YouTube）は最初に公開する
- ショートは本編公開の翌日以降に、1日1本まで、別スロットに分散
- 同一媒体に1日2本以上入れない
- 公開希望日は {{target_publish}}

【出力形式】JSON [{"asset": "main.mp4", "platform": "youtube", "scheduled_at": "2026-07-22T18:00:00+09:00", "reason": "..."}]
```

**設計意図**: スロットを4つに固定するのは、GitHub Actionsの実行回数を抑えるためです（[03-cost.md](./03-cost.md) 3.3）。AIに自由な時刻を出させると、そのために毎分cronが必要になり無料枠を超えます。

### ⑦ 音声ポッドキャスト（エピソード情報一式）

音声は「ながら聴き」で、画面を見ていません。動画とは別物として生成します。

```
文字起こしから、音声ポッドキャストのエピソード情報を生成してください。

【前提】リスナーは移動中・作業中に「聴いて」います。画面は見ていません。

■ エピソードタイトル（3案）
- 全角40文字以内。話数は含めない（RSS側で付与）
- 「誰の何の話か」が音声だけで分かること
- 動画のタイトルと同じにしない（媒体が違えば刺さる言葉も違う）

■ 説明文（2種類）
1) itunes:summary … プレーンテキスト400字以内。1段落目だけで内容が伝わること
2) content_html  … HTML。概要 + チャプター一覧 + ゲスト紹介 + 問い合わせ導線

■ チャプター
- 文字起こしのタイムコードから話題の切れ目を検出
- 5〜10個。各タイトルは全角20文字以内
- 冒頭は必ず 00:00「オープニング」
- 出力は2形式:
  a) JSON: [{"startTime": 0, "title": "オープニング"}, …]
  b) テキスト: "00:00 オープニング\n02:15 給与では勝てない理由\n…"
     （★Spotifyは説明文内のこの表記を自動でチャプター認識するため必須）

■ 出演者
[{"role":"host","name":"…"},{"role":"guest","name":"…","description":"所属・肩書き"}]

■ 検索用キーワード
- 8〜12語。リスナーが実際に検索する語を選ぶ
- 番組名・ゲスト名・企業名・テーマの一般名詞を含める

■ 公開日時案
- 動画本編の公開日と同日または翌日
- ★時刻は指定しない（RSSは反映に数分〜数時間かかるため、日付単位で管理する）

【出力形式】JSON（上記すべてを含む単一オブジェクト）
【文字起こし】{{transcript}}
【ブリーフ】{{brief}}
```

**設計意図**: チャプターを2形式で出させるのは、Apple系アプリはPodcasting 2.0のJSON、Spotifyは説明文内のタイムスタンプ表記と、**対応方式が分かれている**ためです（[09](./09-podcast.md) 9.3）。片方だけだと半分のリスナーで章送りが使えません。

### ⑧ 告知投稿（X等）

```
公開済みコンテンツへの誘導投稿を作成してください。
- 全角120文字以内、URLは本文末尾
- 動画と音声の両方がある場合は「見る/聴く」の選択肢を示す
- ハッシュタグは2つまで
【出力形式】JSON {"text": "...", "hashtags": [...]}
```

## 6.4 生成結果の品質を上げ続ける仕組み

AIの出力をそのまま使い続けるのではなく、**あなたが直した箇所を次の生成に反映させます。**

1. シートの `body` 列をあなたが編集すると、元のAI生成文との差分が `_ai_original` 列（非表示列）に残ります
2. `analyze` コマンドが月に一度、「毎回どこを直しているか」をAIに分析させます
3. 頻出する修正パターンを、共通前提プロンプト（6.2）に追記します

**これを回すと、3か月ほどで「ほぼ直さなくてよい状態」に近づきます。** 修正作業そのものを、システムを賢くする入力に変える設計です。ここがPhase2でクライアントに提供する際の実質的な価値になります。
