# 10. ブラウザ管理画面

## 10.1 技術構成の比較と結論

ご提示の選択肢を、実際に必要な要件で比較しました。

| 構成 | 費用 | 秘匿情報を扱える | どこからでも使える | ファイル操作 | 判定 |
|---|---|---|---|---|---|
| ローカルPCでWeb管理画面 | 0円 | ○ | ✗ PCが必要 | ◎ | △ 併用する |
| GitHub Pages（静的のみ） | 0円 | **✗ 致命的** | ○ | ✗ | ✗ |
| **Cloudflare Pages + Functions** | **0円** | **○** | **○** | △ | ✅ **採用** |
| Vercel 無料枠 | 0円 | ○ | ○ | △ | △ 次点 |
| Google Apps Script | 0円 | ○ | ○ | ✗ | ✗ UI表現力が不足 |

**GitHub Pages のような静的ホスティング単体では成立しません。** SNSのアクセストークンをブラウザ側に置くことになり、投稿権限が漏れると第三者に自社アカウントで投稿されてしまいます。**サーバー側でトークンを保持できる構成が必須**です。

### 採用構成：Cloudflare 一式（すべて無料枠）

```
Cloudflare Pages          管理画面（React + Vite の静的ビルド）
  └ Pages Functions       API。SNSトークン・Sheets認証情報を保持
Cloudflare Access         ログイン認証（Googleアカウント、50人まで無料）
Cloudflare Workers        RSSフィード動的生成
Cloudflare R2             MP3・動画配信（エグレス無料）
Google スプレッドシート      データの正
```

**Vercelではなく Cloudflare を選んだ理由**: R2（ポッドキャスト配信に必須）と Access（認証）が同じアカウントで完結するためです。Vercelを使うとストレージと認証を別サービスで用意することになり、管理対象と障害点が増えます。無料枠の広さも Cloudflare が優位です（Pages 月100GB転送、Functions 1日10万リクエスト）。

### 認証について

**ログイン機能を自前で実装しません。** Cloudflare Access を管理画面のドメインに設定すると、アクセス時にGoogleアカウントでの認証が強制されます。許可するメールアドレスを指定するだけで、パスワード管理・セッション管理・二要素認証がすべて不要になります。50ユーザーまで無料です。

これは単なる手抜きではなく、**認証を自前実装すると必ず脆弱性の温床になる**ためです。投稿権限を持つ管理画面である以上、ここは実績のある仕組みに任せます。

### ローカル併用

同じコードを `npm run dev` でローカル起動できます。大きな動画ファイルを扱う作業（素材投入、R2アップロード）はローカルで、日常の確認・承認はブラウザで、という使い分けです。

### ④ 承認キュー `/approvals`
確認待ちだけを1件ずつ順に処理する画面。**キーボード操作で流せる**ようにします（`J/K` で移動、`E` で編集、`A` で承認、`⌘Enter` で承認して次へ）。Linear の操作感を参照する部分です。5件の承認が1〜2分で終わります。

### ⑤ カレンダー `/calendar`
月表示。媒体別に色分け。ドラッグで投稿日時を変更できます。手動投稿が必要な媒体には ⚠ を表示。

### ⑥ 分析 `/analytics`

要件の項目をタブで分けます。

| タブ | 内容 |
|---|---|
| 概要 | 媒体別KPI、月別推移、登録者・フォロワー増加 |
| コンテンツ別 | 投稿単位のランキング（再生・CTR・保存・DL数） |
| **切り口分析** | `angle` 別の平均成績。「発言引用型」「数値提示型」等のどれが効くか |
| **形式比較** | 長尺 vs ショート vs 音声ポッドキャスト の比較 |
| 媒体比較 | 同一素材が媒体ごとにどう成績が違うか |
| タイトル傾向 | 疑問形/数値入り/引用型 などの型別成績 |
| 商談貢献 | 問い合わせ・商談につながったコンテンツ（手入力と紐づけ） |

**「切り口分析」と「形式比較」が、この管理画面独自の価値です。** 一般的なSNS分析ツールには無い軸で、Content Repurposing を前提にしたデータ構造（[05](./05-data-structure.md) 5.1）があって初めて成立します。

### ⑦ レポート `/reports`
月次レポートをブラウザで表示。`PDF / HTML / Markdown / CSV` で書き出し。AIドラフトをその場で加筆修正して確定できます。

### ⑧ ポッドキャスト管理 `/podcast`
番組設定（タイトル・説明・カテゴリ・カバー画像）、RSSフィードのプレビューと検証、エピソード一覧、配信先の登録状況、Spotify/Apple のCSVインポート。

### ⑨ アイデア `/ideas`
企画ストック。お気に入り、ステータス管理、「収録として起票」ボタン。

### ⑩ 設定 `/settings`
チャンネル連携状況、投稿スロット、AIのブランドボイス設定、通知先。

## 10.3 承認操作

ご要望の操作をすべて実装します。

| 操作 | 挙動 | 安全策 |
|---|---|---|
| AI生成文の修正 | インライン編集。自動保存 | 原文を `ai_original` に保持し、いつでも復元可 |
| 投稿日時の変更 | 日時ピッカー or カレンダーでドラッグ | 過去日時は選択不可 |
| **承認** | `確認待ち` → `承認済み` | 必須項目が空なら承認ボタンを無効化 |
| **承認取消** | `承認済み` → `確認待ち` | 公開済みには適用不可（取り消せないため） |
| **投稿テスト** | 各媒体の下書き/非公開として投稿し、実際の見え方を確認 | YouTubeは`private`、TikTokは`SELF_ONLY`で投稿 |
| **予約投稿** | 承認と同時に予約時刻を確定 | |
| **投稿停止** | 予約済みを取り消す | YouTubeは予約解除API、他は投稿前ならキューから除外 |
| **再投稿** | 失敗したものを再試行 | 二重投稿防止のため、投稿URLが既にある行は再投稿不可 |

**「承認済みでないものは絶対に公開されない」の保証**は、管理画面のボタン制御ではなく**サーバー側で担保**します。投稿APIは `status === "承認済み"` の行だけを取得し、それ以外は存在しないものとして扱います。仮に管理画面に不具合があっても、承認前のコンテンツが公開されることはありません（詳細は [04-approval-flow.md](./04-approval-flow.md)）。

## 10.4 デザイン

### 参考にする考え方

| 参考 | 取り入れるもの |
|---|---|
| **Linear** | キーボード操作、即座に反映されるUI、承認キューの流し方 |
| **Notion** | インライン編集の自然さ、階層の見せ方 |
| **YouTube Studio** | 動画1本を軸にした情報のまとめ方、指標の並べ方 |
| **Spotify for Creators** | 音声コンテンツの一覧・エピソード表現 |
| **Google Analytics** | 期間比較、指標の切り替え方 |

### カラートークン（青・白・グレー）

```css
--bg:            #FFFFFF;   /* 背景 */
--bg-subtle:     #F7F9FC;   /* セクション背景（ごく薄い青みグレー） */
--bg-hover:      #F1F5F9;
--border:        #E3E8EF;
--text:          #1F2933;   /* 本文 */
--text-muted:    #6B7280;   /* 補足 */
--accent:        #2563EB;   /* 青：CTA・選択状態・グラフ主系列 */
--accent-subtle: #EFF6FF;   /* 青の背景（承認済みバッジ等） */
--success:       #0E7490;   /* 完了（緑ではなく青緑。色数を増やさない） */
--danger:        #DC2626;   /* ★投稿失敗のみに使用 */
```

**赤は「投稿失敗」だけに使います。** 色数を絞ることが、企業向けの落ち着いた印象と「どこを見ればいいか一目で分かる」操作性の両方につながります。数値の増減も青とグレーで表現し、減少を赤にはしません（[07](./07-kpi-and-report.md) 7.3と同じ方針）。

### その他

- フォント: `Inter` + `Noto Sans JP`。本文14px、テーブル13px、行間1.7（日本語可読性を優先）
- 角丸6px、影は最小限。区切りは罫線と余白で表現
- サイドバー240px固定、コンテンツ最大1440px
- ステータスは色ドット＋テキスト（色だけに依存させない）
- ダークモードは初期リリースでは対応しない（企業提出用のレポートが主目的のため、優先度が低い）

**「映像制作会社らしさ」の出し方**: 装飾を足すのではなく、**サムネイル・動画・波形などのビジュアル要素を大きく扱う**ことで表現します。一覧ではサムネイルを実寸に近い比率で表示し、ポッドキャストは波形を添える。UIそのものは徹底して無色透明にし、コンテンツ側を主役にする方針です。
