# 12. Premiereへ何を渡せるか — 能力の境界

「Premiereを開いた時点で編集の90%が完了している」を実現するには、**Adobeが公式に受け取れる形式で何が渡せて何が渡せないか**を正確に把握する必要があります。ここを楽観的に見積もると、実装後に「思っていたものと違う」となります。

2026年7月時点の公式仕様に基づく調査結果です。

---

## 12.1 結論：3つの経路を組み合わせる

| 経路 | 何を渡すか | 公式サポート | 将来の安定性 |
|---|---|---|---|
| **A. FCP7 XML** | 素材配置・同期・カメラ切替・BGM・OP/ED・マーカー・ショートシーケンス・音量 | ✅ 公式 | ✅ 安定 |
| **B. SRTファイル群** | 字幕・話者名・強調テロップ・チャプター | ✅ 公式 | ✅ 安定 |
| **C. 事前処理済みメディア** | ノイズ軽減・ラウドネス調整済みの音声 | ✅ Premiere不要 | ✅ 安定 |
| D. UXPプラグイン | 上記の読み込み自動化、マーカー色、MOGRT挿入 | ⚠️ 一部未確認 | Phase2で判断 |
| ✗ ExtendScript | — | 2026年9月終了 | **採用しない** |

**A・B・Cだけで Phase1 は成立します。** UXPプラグインは「あると快適」ですが、無くても90%に到達できる構成にしました。開発・署名・インストールの手間を Phase1 に持ち込まない判断です。

**ExtendScript は使いません。** `importMGT()` などテロップ挿入に使える便利なAPIがありますが、**2026年9月でサポート終了**が公式告知済みです。あと2か月しかないものの上に Phase1 を建てるのは負債になります。

## 12.2 渡せるもの（○）

| 項目 | 経路 | 実現方法 |
|---|---|---|
| **素材配置** | A | 全カメラ・音声をトラックに配置 |
| **音声同期済み** | A | ★AIが波形の相互相関でオフセットを算出し、**XMLの時点で揃えて配置**。編集者は同期作業ゼロ |
| **カメラ切り替え** | A | AIの切替案をカットとして適用済みの本編シーケンス |
| **BGM配置** | A | 音声トラックに配置、音量レベルも指定 |
| **オープニング / エンディング** | A | 頭と尾に配置 |
| **マーカー**（名前＋コメント） | A | 種類を名前の接頭辞で表現（後述12.3） |
| **ショート用シーケンス** | A | 1080×1920のシーケンスを本数分生成 |
| **クリップ音量** | A | クリップ単位のレベル指定 |
| **字幕** | B | SRT → キャプショントラック |
| **話者名** | B | ★別トラックのSRTとして生成（後述12.4） |

| **チャプター** | A + B | タイムラインマーカー ＋ YouTube用テキスト |

| **音声の要確認情報** | A | クリッピング・大きなノイズ・チャンネル異常を `[CHECK]` マーカーで提示 |

## 12.3 渡せないもの（×）と、その代わり

正直にお伝えすべき制約です。**すべてに代替手段を用意しました。**

### ① マルチカメラソースシーケンスは自動生成できない

**制約**: マルチカメラソースシーケンスの作成と自動同期は、**スクリプト（ExtendScript・UXPとも）から実行できません。** Premiereのメニュー操作専用の機能です。

> **⚠️ 前回の記載を訂正します。** 前回「3クリップを選択 → マルチカメラソースシーケンスを作成 → 同期ポイント『イン点』で完了（3クリック）」と書きましたが、**これは誤りです。** プロジェクトパネルの素材クリップは全てイン点が0のため、「イン点」同期では**全カメラが頭揃えになり、AIが算出したオフセットが反映されません。** 算出したオフセットをマルチカメラソースシーケンスに注入する手段はありません。

**代替（採用する方式）**: マルチカメラソースシーケンスに頼らない構成にします。

| 生成物 | 役割 |
|---|---|
| **`01_本編`** | ★**主たる成果物。** カメラ切替案をV1上の連続したカットとして適用済み。同期オフセットは各クリップのイン点に反映済み。編集者は通常の編集操作（リップル・ロール・置き換え）でそのまま作業を続けられる |
| **`02_同期確認_全カメラ`** | 全カメラを尺いっぱいに重ねて配置（V1=引きのみ有効、寄りは無効）。トラックのオン/オフで同期を目視確認できる |

**`01_本編` が「90%完了」の実体です。** マルチカメラ編集の目的は「同期された複数アングルを切り替えながら組む」ことですが、その切り替えはすでに適用済みなので、**マルチカメラソースシーケンスを作る必要自体がありません。**

**それでもPremiereのマルチカメラモニター（数字キーでアングル切替）を使いたい場合**は、Premiere自身の音声同期でマルチカメラソースシーケンスを作る必要があります（1エピソードあたり1〜2分の解析待ち）。**この操作は我々のオフセットを使えないため、実測項目4には「マルチカメラを使わない前提の同期確認操作数」を計上します。**

### ② マーカーの色分けはXMLでは指定できない

**制約**: FCP7 XMLのマーカー要素は名前・コメント・イン/アウトのみで、**色属性を持ちません。**

**代替**: 種類を**名前の接頭辞**で表現します。Premiereのマーカーパネルで並べ替え・検索ができるため、実用上は色分けと同等に機能します。

```
[SHORT-1] 辞退率の話 ／ 数値提示型・保存されやすい
[LAUGH]   笑い（3秒）
[KEY]     重要発言「採用は広告じゃなくて、正直な自己紹介」
[RETAKE]  言い直し候補（3回目のテイクが最良）
[CHECK]   要確認：音声にノイズ
[SPONSOR] スポンサー紹介
[OP] / [ED]
[TOPIC]   話題区切り：社員インタビュー動画の効果
```

色分けは **Phase2のUXPパネル**で対応します（マーカーAPIはUXPのサンプルに含まれているため、実現可能性は高いと判断しています）。

### ③ MOGRT（アニメーション付きテロップ）の自動挿入は現時点で確約できない

**制約**: ExtendScriptには `importMGT()` がありますが2026年9月終了。**UXPの公式サンプルにMOGRT関連は含まれておらず**、対応状況が確認できていません。

**代替**: テロップを**SRTベース**で渡します（12.4）。アニメーションは付きませんが、**スタイルは Premiere の Essential Graphics で1回設定すれば全体に適用**されます。WORKAHOLICのテロップテンプレートをキャプションスタイルとして登録しておけば、ブランドの見た目は保てます。

アニメーション付きテロップが必要な箇所（オープニングのタイトルなど）は数が少ないため、編集者が手動で入れるのが現実的です。**Phase2でUXPのMOGRT対応を確認し、可能なら自動化します。**

### ④ 縦型の話者追従（Auto Reframe）は指定できない

**制約**: リフレーミングの座標をXMLで渡せません。

**代替**: ショートシーケンスを1080×1920で生成しておき、**Premiereの自動リフレームを適用**（1シーケンス2クリック）。Adobe純正の解析なので精度が高く、自前実装より確実です。

### ⑤ ノイズ軽減などのエフェクト設定はXMLで渡せない

**代替**: **Premiereに渡す前にffmpegで補正音声を別ファイルとして作ります**（経路C）。エフェクトを渡す必要がなくなります。

**★補正は非破壊です。原音を上書きしません**（詳細は12.7）。原音がPremiereの基本トラックで、補正音は別トラックに並びます。

## 12.4 テロップを「3本のSRT」として渡す設計

テロップ自動生成の要望に対する、**完全に公式サポートされた実現方法**です。Premiereは複数のキャプショントラックを持てるため、これを利用します。

| トラック | 内容 | スタイル（1回設定） | 例 |
|---|---|---|---|
| **字幕** | 全発言の書き起こし | 下部・中サイズ・縁取り | `採用は広告じゃなくて` |
| **話者名** | 話者が切り替わるたびの名前 | 左下・小サイズ・帯付き | `山田太郎（株式会社◯◯ 人事部長）` |
| **強調テロップ** | AIが選んだ重要フレーズ（1話5〜15箇所） | 中央・大サイズ・太字 | `辞退率を見ろ` |

各SRTをPremiereに読み込み、キャプショントラックに置いて**スタイルを1回適用するだけ**です（トラックごとに1回、計3回の操作）。

**この方式を選んだ理由**: MOGRT挿入APIの将来が不確実な一方、SRTのキャプション読み込みはAdobeが公式ドキュメントで案内している安定した機能です。**確実に動くものでPhase1を組み、不確実なものはPhase2で検証する**という切り分けにしました。

### 字幕の生成ルール
- 1行あたり全角14文字前後、最大2行（縦型での可読性）
- 句読点は入れない（読みのリズムを妨げるため）
- 単語単位のタイムコードから、**息継ぎの位置で改行**する
- フィラー（「えー」「あのー」）は**字幕からは除くが、音声はカットしない**（12.5）

## 12.5 AIが絶対に行わないこと

ご指示のとおり、以下は**実装しません。** 単に「初期設定でオフ」にするのではなく、**そもそも機能として作りません。**

| 禁止事項 | 実装方針 |
|---|---|
| **無音・間・沈黙の削除** | ★**検出機能そのものを作りません。** マーカーとしても提示しません |
| 言い直しの削除 | 検出はするが、`[RETAKE]` マーカーで**提示のみ**。カットは一切しない |
| 間・笑い・リアクションの取捨 | AIは判断しない。`[LAUGH]` マーカーで位置を示すだけ |
| カットのテンポ調整 | しない |
| 演出的判断 | しない |

**前回の設計を訂正します。** 前回は「カット候補マーカー」に沈黙検出を含めていましたが、これは削除しました。**会話の間や空気感が作品の一部**というご指摘に沿うなら、沈黙を「候補」として提示することすら編集判断を誘導します。検出しないのが正しい設計です。

代わりに `[LAUGH]`（笑いの位置）を追加しました。**削るためではなく、活かすため**の情報です。笑いはショート候補としても、テンポの良い箇所の目印としても価値があります。

## 12.6 Phase1完了時に、編集者が行う操作（目標値）

> ⚠️ **以下は実素材での検証前の目標値であり、確定値ではありません。** 実測して報告します（12.8）。

「90%完了」が具体的に何を意味するかを、残る10%の側から示します。

```
1. ep012.fcp7.xml を読み込む                                … 1操作
2. メディアの再リンク（必要な場合）                           … 不明（実測対象）
3. 02_同期確認_全カメラ でトラックを切り替えて同期を目視確認      … 3操作
4. SRT 3本を読み込み、各トラックにスタイル適用               … 6操作
5. ショートシーケンスに自動リフレームを適用（採用する本数分）   … 本数×2操作
─────────────────────────────────────────
ここまで機械的な操作。★想定15操作・目標3分以内
─────────────────────────────────────────
6. ★本編を通して確認し、カメラ切替・テンポ・間を調整         ← 編集者の本来の仕事
7. ★強調テロップの位置と文言を確認                          ← 同上
8. ★ショートの採否を決める                                  ← 同上
9. 書き出し
```

**素材の開始タイミングがずれている場合の扱いは2方式から選べます**（実装済み）。

| 方式 | 挙動 |
|---|---|
| **`preserve`（既定）** | 各素材の尺を最大限残し、参照できない先頭部分のみイン点を0に丸める。負のオフセットを持つカメラの冒頭が数フレーム揃わない |
| `common` | 全カメラが揃う共通区間だけでシーケンスを作る。冒頭から完全に揃うが尺が短くなる |

実収録では収録開始から本編開始まで余白を取るため、既定の `preserve` で問題にならない想定です。実素材で不都合が出たら設定1つで `common` に切り替えられます。

**2（メディア再リンク）は未知数として明示しています。** FCP7 XMLはメディアを絶対パスで参照するため、パスが一致すれば再リンクは発生しませんが、外付けSSDのマウント名が変わる等の条件で発生しえます。ここが操作数に効く可能性があるため、実測項目に入れています。

**6〜8が編集者に残る本質的な作業**であり、ここはAIが代替すべきではない領域です。「編集者は演出・ストーリー・テンポ・感情表現に集中できる状態」は、この配分で実現されます。

1〜5はPhase2のUXPパネルで「1クリック」にまとめられる見込みですが、**実測で3分以内に収まるならプラグイン開発を先行させる価値は低い**と判断します。実測結果が判断材料になります。

## 12.7 音声補正は非破壊（原音を上書きしない）

**原則**: 補正処理は**原音を一切変更しません。** 補正音は別ファイルとして生成し、Premiereでは別トラックに並べます。編集者が原音と補正音を聴き比べて選べる状態にします。

### 生成されるファイル

```
content/2026-07/ep012/
├── raw/audio/
│   ├── mic_A.wav          ★原音（読み取り専用として扱う。絶対に上書きしない）
│   └── mic_B.wav          ★原音
└── audio/processed/       ← 補正音は必ず別ディレクトリに出力
    ├── mic_A.corrected.wav
    ├── mic_B.corrected.wav
    └── correction-report.json   何をどれだけ補正したかの記録
```

**実装上の保証**: 出力先が入力ファイルと同一パスになる場合、処理を実行せずエラーで停止します。「上書きしないよう気をつける」ではなく、**上書きが起こり得ない構造**にします。

### Premiereでのトラック構成

```
A1  原音（mic_A）        ★有効 ← 基本トラック
A2  原音（mic_B）        ★有効 ← 基本トラック
A3  補正音（mic_A）       無効（ミュート）← 聴き比べ用
A4  補正音（mic_B）       無効（ミュート）← 聴き比べ用
A5  BGM                 有効
```

**原音を基本トラックとして有効にし、補正音はミュート状態で並べます。** 編集者はトラックのミュートを切り替えるだけで比較でき、補正を採用する場合は原音をミュートします。

FCP7 XMLの `<track><enabled>FALSE</enabled></track>` でトラック単位の無効化を表現します。

### 案件ごとの設定

```yaml
# config/audio.yml（案件・エピソード単位で上書き可能）
correction:
  enabled: true          # false にすると補正音を生成せず、原音のみ配置
  noiseReduction: true   # afftdn
  loudness: true         # -14 LUFS（動画用）
  gainBalance: true      # 話者ごとのマイク距離差の補正
  targetLufs: -14
```

`enabled: false` の場合、補正音のトラックは作られず、原音だけのシンプルな構成になります。**補正が不要な収録（既に整音済みの素材を受け取る場合など）で、余計なトラックが増えないようにするためです。**

### 要確認情報（自動補正しないが、必ず知らせる）

以下は**自動で直しません。** `[CHECK]` マーカーと管理画面で編集者に提示します。判断が必要な問題を機械的に補正すると、かえって取り返しがつかなくなるためです。

| 検出項目 | 判定基準 | 表示例 |
|---|---|---|
| **クリッピング** | 0 dBFS 到達サンプルが連続 | `[CHECK] mic_A クリッピング（12:34, 0.4秒）` |
| **大きなノイズ** | 突発的なピーク（クリック・物音・咳） | `[CHECK] 突発ノイズ（08:12）` |
| **チャンネル異常** | 片チャンネル無音、左右逆相、モノラル素材のステレオ収録 | `[CHECK] mic_B 右チャンネルが無音` |
| 音量の極端な差 | 話者間で6dB以上 | `[CHECK] mic_B が mic_A より9dB小さい` |
| 無音区間 | ★**検出しません**（12.5） | — |

## 12.8 実測計画（目標値の検証）

12.6の数値は目標値です。**実素材3本以上で計測し、中央値を出して目標との差を報告します。**

### 計測項目

| # | 項目 | 単位 | 目標 |
|---|---|---|---|
| 1 | 素材登録からFCP7 XML生成までの時間 | 分 | 25分以内 |
| 2 | PremiereへのXML読み込み時間 | 秒 | 60秒以内 |
| 3 | メディア再リンクに必要な操作数 | 操作 | 0 |
| 4 | 同期確認に必要な操作数 | 操作 | 3以下 |
| 5 | 字幕適用に必要な操作数 | 操作 | 6以下 |
| 6 | 縦型シーケンス調整に必要な操作数 | 操作／本 | 2 |
| 7 | 編集者が初稿を確認する時間 | 分 | — （基準値として記録） |
| 8 | **XMLの読み込みエラー率** | % | **0%** |
| 9 | **字幕・マーカーの欠落率** | % | **0%** |

### 計測方法

- 素材は**3本以上**（できれば収録条件の異なるもの：長尺／短尺、2名／3名、ノイズの有無）
- 各項目を1本ずつ記録し、**中央値**で評価（平均だと1本の外れ値に引っ張られるため）
- 操作数は「クリック・キー操作・ドラッグ」を1操作として数える
- 8・9は自動チェックを併用（生成したマーカー数・字幕キュー数と、Premiere側の実数を突き合わせる）
- 計測結果は `docs/measurements/` に記録し、目標との差と原因を報告

### 目標を外した場合の対応方針

| 外れた項目 | 対応 |
|---|---|
| 8（読み込みエラー率 > 0%） | ★**最優先で修正。** XML生成の仕様を見直す。改善しなければEDL経由やUXPへ方針変更 |
| 9（欠落率 > 0%） | 同上。データが失われるのは許容できない |
| 3（再リンクが発生） | パス解決の方式を見直す（相対パス化、素材ルートの設定化） |
| 1・2（時間） | 実用上の許容範囲かを判断。処理の並列化や解析モデルの軽量化を検討 |
| 4・5・6（操作数） | 合計が目標を超えるなら、**UXPパネルの前倒し**を検討する判断材料にする |

**8と9は品質の下限です。** ここが0%にならない限り、他の数値がどれだけ良くても実運用には乗せません。
