# 11. 編集パイプライン（本システムの中核）

## 11.0 位置づけ

> **本システムはPremiere Proを置き換えません。Premiereの編集時間を短縮するAIアシスタントエディターです。**
>
> **目標：Premiereを開いた時点で編集作業の90%が完了している状態。**

編集者のクリエイティブを代替せず、編集者が最も時間を使う **準備・整理・反復作業** をAIが引き受けます。演出・ストーリー・テンポ・感情表現の判断は編集者に残します。

「渡せるもの／渡せないもの」の正確な境界は [12-premiere-capability-matrix.md](./12-premiere-capability-matrix.md) にまとめました。**先にそちらを読んでいただくと、本書の設計判断の理由がわかります。**

```

   ↓
━━━ Premiere編集プロジェクト生成 ━━━
   ep012.fcp7.xml       本編＋ショートシーケンス（同期・切替・BGM・OP/ED済み）
   字幕/subtitle.srt     字幕

   ↓

   ↓

   ↓
$ contentos watch が検知 → 承認キューへ
   ↓
ブラウザ管理画面で承認（Premiereは編集、ブラウザは確認）
   ↓
投稿（承認済みのみ） → 分析 → レポート・改善提案
```

## 11.2 入力素材

```
content/2026-07/ep012_採用ブランディング/
├── brief.md                    テーマ・出演者・要点（3分で記入）
├── raw/
│   ├── wide.mp4                引き映像（マスター音声入り）★必須
│   ├── cam_A.mp4               出演者A寄り
│   ├── cam_B.mp4               出演者B寄り
│   ├── cam_C.mp4               （3人目以降も同じ規約で追加可）
│   └── audio/
│       ├── mic_A.wav           別録り音声（あれば話者判定が大幅に正確になる）
│       ├── mic_B.wav
│       └── mic_C.wav
└── （生成物は後述）
```

### 出演者3人以上への対応

**素材の命名規約だけで拡張できる構造**にします。`cam_C` / `mic_C` を置けば自動的に3人目として扱われ、話者判定・カメラ切替・話者名テロップに反映されます。人数の上限をコードに持たせません。

出演者の名前は `brief.md` で対応づけます。

```markdown
---
speakers:
  A: { name: "岸本", role: host }
  B: { name: "山田太郎", title: "株式会社◯◯ 人事部長", role: guest }
  C: { name: "佐藤花子", title: "同 採用担当", role: guest }
---
```

### 共通アセット（番組で使い回すもの）

```
assets/
├── opening.mp4          オープニング
├── ending.mp4           エンディング
├── logo.png
├── bgm/
│   ├── main_theme.wav
│   └── bridge.wav
└── caption-styles/      Premiereのキャプションスタイル（字幕/話者名/強調）
```

`assets/` は1回用意すれば以降すべてのエピソードで自動使用されます。

## 11.3 AI解析の中身

すべてローカル実行・費用0円です。**AIモデルに投げるのは「意味の判断が必要な処理」だけ**に絞り、機械的に判定できるものはプログラムで処理します。これが無料枠内で回し続けるための基本方針です。

### ① 音声同期（プログラム処理）

各カメラのスクラッチ音声と引き映像の音声を**相互相関**で突き合わせ、フレーム単位のオフセットを算出します。

```
wide.mp4    0フレーム（基準）
cam_A.mp4   +37フレーム
cam_B.mp4   -12フレーム
mic_A.wav   +41フレーム
```

**このオフセットをXMLの配置位置に反映するため、Premiereを開いた時点ですべて揃っています。** マルチカメラ編集で最も時間がかかる作業がゼロになります。

### ② 話者判定（プログラム処理を優先）

| 素材の状況 | 判定方法 | 精度 |
|---|---|---|
| **別録り音声あり** | 各マイクの音量を比較し、最も大きいマイクの話者を「発話者」とする | **高い** |
| 別録り音声なし | 話者分離（pyannote・ローカル・無料）で推定 | 中 |

**ピンマイクを人数分使っていただけると、話者判定はほぼ完璧になります。** そしてこの精度が、カメラ切替案と話者名テロップの精度を直接決めます。ここは機材運用側で担保するのが最も確実です。

### ③ 文字起こし（faster-whisper・ローカル）

単語単位のタイムコード付きで書き起こします。

| 設定 | 値 | 理由 |
|---|---|---|
| モデル | **`large-v3`** | 実測で `small` は業務用語を誤認識（「自己紹介」→「事故紹介」、「辞退率」→「自体率」）。`large-v3` で解消 |
| compute type | **`int8`** | Apple Siliconで最速（`float32` の約1.7倍速く、精度差なし） |
| **VAD（無音除去）** | **無効** | ★沈黙・間は作品の一部。文字起こしの都合で時間軸を詰めない |

**確信度の低い語を「聞き直したほうがよい箇所」として提示します。** 実測で、誤認識した語は確信度が低く出ることを確認しました（0.69 / 0.77 に対し、他は0.95以上）。**自動修正はしません** — 誤った自動修正のほうが害が大きいためです。

検証記録: [whisper-model-comparison.md](./measurements/whisper-model-comparison.md)

### ④ 話題区切り・チャプター（AI）

文字起こし全文から話題の切れ目を検出し、章タイトルを生成します。この結果が **タイムラインマーカー・YouTubeチャプター・ポッドキャストのチャプター** の3箇所で共有されます。

### ⑤ 笑い・盛り上がり・強調ポイントの検出

| 対象 | 検出方法 |
|---|---|
| **笑い** | ★**補助判定**。音量変動の深さと速さ（音節速度より上）から候補を出し、確信度を付ける。**実素材では文字起こしの「（笑）」相当の表記と人の確認を主とする** |
| **盛り上がり** | 複数話者の同時発話密度、音量の立ち上がり、発話速度の上昇 |
| **強調ポイント** | AIが文字起こしから「この一文だけで意味が通り、印象に残る発言」を抽出 |

**いずれも削除のためではなく、活かすための情報です。** 笑いと盛り上がりはショート候補の有力な手がかりであり、強調ポイントは強調テロップとショートのフックになります。

**笑い検出は自動でカメラ切替を確定させません。** 音量変動だけで笑いを確実に判別することはできないため、確信度が低い候補（既定0.5未満）はカメラ切替の根拠にせず、`[LAUGH]` マーカーに「要確認」と付けて編集者の判断に委ねます。確信度が十分な場合のみ引きへの切替案に反映します。しきい値は `config/camera-rules.yml` の `minLaughterConfidence` で調整できます。

### ⑥ カメラ切り替え案（ルールベース）

話者判定の結果から、機械的なルールで切替案を組みます。

```
基本ルール:
  Aが話している        → cam_A
  Bが話している        → cam_B
  複数人が同時に話す    → wide
  笑いが起きている      → wide（★確信度が十分な場合のみ。低い場合はマーカーのみ）
  発言の直後2秒        → 聞き手側のカメラ（リアクション）
  誰も話していない      → 直前のカメラを維持（★切らない）

制約:
  最短ショット長 2.5秒（頻繁な切替を防ぐ）
  発話開始の0.3秒前に切替（頭の音を欠けさせない）
  同一カメラが20秒を超えたら、リアクションカットを挿入
```

**AIモデルではなくルールで組む理由**: 切替の理由が明示的で、編集者が「なぜここで切れているか」を理解でき、ルール自体を調整できるからです。AIに任せると理由が説明できず、直したいときに直せません。ルールは設定ファイル（`config/camera-rules.yml`）に外出しし、運用しながら調整します。

**編集者はすべての切替を自由に変更できます。** カットとして置いてあるだけなので、通常の編集操作で動かせます。

### ⑦ ショート候補の抽出（AI）

強調ポイント・笑い・盛り上がりの検出結果を入力に、AIが候補を選定します。各候補について生成するもの:

| 項目 | 内容 |
|---|---|
| 開始位置 / 終了位置 | フレーム単位 |
| 縦型構図 | シーケンスを1080×1920で生成（話者追従はPremiereの自動リフレーム） |
| タイトル | ショートのタイトル |
| **冒頭フック** | 最初の2秒で言うべき一文 |
| 投稿文 | 媒体別（YouTube Shorts / Reels / TikTok） |
| ハッシュタグ | 媒体別 |
| **選定理由** | ★なぜこの区間を選んだか |

**選定理由を必ず添えます。** 理由が書かれていない提案は、採否の判断に時間がかかるだけで価値がありません。

**候補は多めに（6〜8本）出し、編集者が採用する本数だけ承認します。** 全部作らせるのではなく選ばせるほうが、結果的に質が上がります。

### ⑧ 音声処理（★非破壊。原音を上書きしない）

**原音は絶対に変更しません。** 補正音は別ファイルとして生成し、Premiereでは別トラックに並べます。

| 処理 | 方法 |
|---|---|
| ノイズ軽減 | `afftdn` / `arnndn`（環境ノイズ・空調音の低減） |
| ラウドネス調整 | `loudnorm` 2パス。**動画用 -14 LUFS**（YouTubeの正規化基準に合わせる） |
| 音量バランス | 話者ごとのゲイン調整（マイク距離差の補正） |
| トゥルーピーク | -1.0 dBTP 以下 |

```
raw/audio/mic_A.wav              ★原音（読み取り専用として扱う）
audio/processed/mic_A.corrected.wav   補正音（別ディレクトリ・別ファイル）
```

**Premiereでのトラック構成**

```
A1  原音（mic_A）      ★有効 ← 基本トラック
A2  原音（mic_B）      ★有効 ← 基本トラック
A3  補正音（mic_A）     無効（ミュート）← 聴き比べ用
A4  補正音（mic_B）     無効（ミュート）← 聴き比べ用
A5  BGM               有効
```

編集者はトラックのミュートを切り替えるだけで原音と補正音を比較でき、補正を採用する場合は原音側をミュートします。**どちらを使うかの判断は編集者に残します。**

**補正の実行自体を案件ごとに切り替えられます**（`config/audio.yml` の `correction.enabled`）。既に整音済みの素材を受け取る場合、余計なトラックが増えません。

**要確認情報は自動補正せず提示します**: クリッピング・突発ノイズ・チャンネル異常・話者間の極端な音量差を検出し、`[CHECK]` マーカーと管理画面に出します。判断が必要な問題を機械的に補正すると、かえって取り返しがつかなくなるためです。**無音区間は検出しません**（11.5）。

詳細は [12](./12-premiere-capability-matrix.md) 12.7 を参照してください。

**Premiereのエフェクトとして渡さない理由**: エフェクト設定はXMLで渡せないためです。音声ファイルを別途用意すれば、この制約を回避しつつ非破壊性も保てます。

## 11.4 生成されるPremiereプロジェクト

```
ep012.fcp7.xml を読み込むと、以下がプロジェクトに入ります。

📁 ep012
├── 🎬 01_本編                    [1920×1080]
│    V3  cam_B（切替済み）
│    V2  cam_A（切替済み）
│    V1  wide ＋ opening / ending
│    A5  BGM
│    A3-A4 補正音（ミュート・聴き比べ用）
│    A1-A2 ★原音（有効・基本トラック）
│    マーカー: [TOPIC] [LAUGH] [KEY] [RETAKE] [SHORT-n] [OP] [ED] [SPONSOR]
│
├── 🎬 02_同期確認_全カメラ          [1920×1080]
│    V1 引き（有効）／V2 cam_A・V3 cam_B（無効）
│    トラックのオン/オフで同期を目視確認できる
│
├── 🎬 03_short_01_辞退率の話        [1080×1920]
├── 🎬 04_short_02_正直な自己紹介     [1080×1920]
├── 🎬 05_short_03 … （候補は6〜8本）
│
└── 📁 素材
     wide.mp4 / cam_A.mp4 / cam_B.mp4（同期オフセット反映済み）
     ★原音 / 補正音 / BGM / opening / ending
```

別ファイルとして生成されるもの:

```
字幕/subtitle.srt    字幕
字幕/speaker.srt     話者名テロップ
字幕/emphasis.srt    強調テロップ
チャプター/youtube.txt  YouTube概要欄用のタイムスタンプ
transcript.json      単語単位のタイムコード付き文字起こし
analysis.json        解析結果すべて（管理画面が読む）
```

### マーカーの種類

| 接頭辞 | 意味 | コメント欄の内容 |
|---|---|---|
| `[TOPIC]` | 話題区切り | 章タイトル |
| `[LAUGH]` | 笑い | 長さ・関与した話者 |
| `[KEY]` | 重要発言 | 発言の引用 |
| `[SHORT-n]` | ショート候補区間 | タイトル＋**選定理由** |
| `[RETAKE]` | 言い直し候補 | どのテイクが最良か（★削除はしない） |
| `[CHECK]` | 要確認 | ノイズ・映像の乱れなど |
| `[SPONSOR]` | スポンサー紹介 | — |
| `[OP]` / `[ED]` | オープニング / エンディング | — |

色分けはXMLでは指定できないため接頭辞で表現します（[12](./12-premiere-capability-matrix.md) 12.3②）。Premiereのマーカーパネルで並べ替え・検索ができるため、実用上は同等に機能します。

## 11.5 AIが絶対に行わないこと

ご指示のとおり、**機能として作りません**（設定でオフにするのではありません）。

| | 方針 |
|---|---|
| **無音・間・沈黙の削除** | ★**検出機能そのものを作りません。** マーカーとしても出しません |
| 言い直しの削除 | `[RETAKE]` マーカーで**提示のみ**。カットしない |
| 間・笑い・リアクションの取捨 | 判断しない。位置を示すだけ |
| カットのテンポ調整 | しない |
| 演出的判断 | しない |

**前回の設計を訂正します。** 前回は沈黙検出を「カット候補マーカー」に含めていましたが削除しました。**会話の間や空気感が作品の一部**であるなら、沈黙を候補として提示することすら編集判断を誘導します。検出しないのが正しい設計です。

カメラ切替についても、**「誰も話していないときは切らない」**をルールに入れています。間を映像の切り替えで埋めようとしないためです。

## 11.6 書き出しから投稿への接続

```
Premiereで書き出し（Media Encoderのウォッチフォルダ or キュー）
   ↓ 書き出し先: exports/
$ contentos watch が検知
   ↓
・本編MP4 → 承認キューへ（投稿文は解析時に生成済み）
・ショートMP4 → 採用されたものだけ承認キューへ
・（Phase3）MP3生成 → ポッドキャスト
   ↓
ブラウザで承認 → 承認済みのみ投稿
```

**未承認データは絶対に投稿されません。** 投稿処理は `承認済み` ステータスの行だけを取得するホワイトリスト方式で、[`packages/core/src/publish-guard.ts`](../packages/core/src/publish-guard.ts) に実装済み・テストで固定済みです（[04](./04-approval-flow.md)）。

## 11.7 ブラウザ管理画面の役割（編集はしない）

ご指示のとおり、**管理画面は編集画面ではなく確認画面**です。

| 画面 | 内容 |
|---|---|
| 素材一覧 | 各エピソードの素材の揃い具合、解析の進捗 |
| 編集状況 | 素材準備中 / 解析中 / 編集中 / 確認待ち / 承認済み … |
| **ショート候補一覧** | 6〜8本の候補を、選定理由・フック・尺つきで一覧。**採否をここで決める** |
| テロップ確認 | 字幕・話者名・強調テロップの文言を確認・修正 |
| 投稿文確認 | 媒体別の投稿文・ハッシュタグを確認・修正 |
| 承認 | 承認 / 承認取消 |
| **再生成** | 気に入らない生成結果だけを作り直す |

**本格的な編集はPremiereで行います。** 管理画面に映像編集機能は作りません。役割を混ぜると、どちらも中途半端になります。

## 11.8 処理時間の見込み（30分素材・M系Mac想定）

| 処理 | 所要 |
|---|---|
| 音声同期 | 1〜2分 |
| 文字起こし（faster-whisper large-v3） | 5〜10分 |
| 話者判定 | 1分（別録り音声あり）／5分（分離処理） |
| 笑い・盛り上がり検出 | 1分 |
| 音声処理（ノイズ・ラウドネス） | 2〜3分 |
| AI解析（話題区切り・ショート候補・文面生成） | 2分 |
| XML・SRT生成 | 数秒 |
| **合計** | **15〜25分** |

撮影後に `analyze` を実行して席を離れ、戻ってきたらPremiereを開ける状態になっています。
