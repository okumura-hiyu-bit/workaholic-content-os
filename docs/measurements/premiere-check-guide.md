# Premiere検証ガイド（合成素材）

実素材の前に、XML連携部分だけを検証するための手順と期待値。

## 検証対象

```
.selfcheck/検証素材 fixture/selfcheck.fcp7.xml
```

生成するコマンド（すでに生成済みですが、作り直す場合）:

```bash
npm run selfcheck
```

> ⚠️ **映像はダミー（グレー1色）です。** 映像の中身は検証対象ではありません。確認するのは**XMLの構造・パス解決・トラック構成・マーカー・オフセット**です。

## 素材の構成と正解値

| 素材 | 正解オフセット | 意味 |
|---|---|---|
| `wide.mp4` | 0秒（基準） | 引き映像 |

## 確認項目と期待値

### 1. XMLがエラーなく読み込めるか

`ファイル > 読み込み` で `selfcheck.fcp7.xml` を選択。

- [ ] エラーダイアログが出ない
- [ ] 警告が出た場合はその文言を記録

### 2. ダミー素材が自動リンクされるか

- [ ] 「メディアをリンク」ダイアログが**出ない**
- [ ] 出た場合、どの素材が見つからなかったかを記録（★項目8に直結します）

### 3. `01_本編` のカメラ切替が想定どおりか

期待されるカット（5クリップ、V1上の連続したカット）:

| # | 開始 | 終了 | カメラ | 理由 |
|---|---|---|---|---|
| 1 | 0:00.00 | 0:09.69 | cam_A | Aの発話 |
| 2 | 0:09.69 | 0:19.69 | cam_B | Bの発話 |
| 3 | 0:19.69 | 0:25.69 | wide | **同時発話 → 引き** |
| 4 | 0:25.69 | 0:33.69 | cam_A | Aの発話 |
| 5 | 0:33.69 | 0:40.00 | wide | **笑い → 引き** |

- [ ] 映像トラックは **V1のみ**、クリップは **5個**
- [ ] クリップ名に切替理由が入っている（例: `cam_A.mp4 (speech)`）
- [ ] **沈黙（8-10秒 / 18-20秒 / 32-34秒）でカットが増えていない**
  - 8-10秒はクリップ1の途中、18-20秒はクリップ2の途中、32-34秒はクリップ4の途中にあるはずです

### 4. `02_同期確認_全カメラ` の配置とオフセットが正しいか

- [ ] 映像トラックが **3本**（V1=wide、V2=cam_A、V3=cam_B）
- [ ] **V1のみ有効**、V2・V3は無効（目のアイコンがオフ）
- [ ] 各クリップは 0フレームから1200フレームまで
- [ ] **ソースのイン点**が以下になっている（クリップを選択して情報を確認）

| トラック | 素材 | イン点 |
|---|---|---|
| V1 | wide.mp4 | 0フレーム |
| V2 | cam_A.mp4 | **36フレーム**（+1.2秒） |
| V3 | cam_B.mp4 | 0フレーム（−0.4秒は負のため0に丸め） |

- [ ] V2・V3を順に有効にして、映像の切り替わりが揃っているか目視（ダミー映像なので音声波形で確認するほうが確実です）

> **オフセットが負の場合**（cam_B）はイン点を0に丸めています。素材の先頭より前を参照できないためです。実素材では、負のオフセットを持つカメラの冒頭が数フレーム欠けます。**この挙動が問題になるかを判断していただきたい点です。**

### 5. 原音・補正音が別トラックになっているか

`01_本編` の音声トラック構成:

| トラック | 内容 | 状態 |
|---|---|---|
| A1 | 原音 mic_A.wav | **有効** |
| A2 | 原音 mic_B.wav | **有効** |
| A3 | 補正音 mic_A.corrected.wav | **ミュート** |
| A4 | 補正音 mic_B.corrected.wav | **ミュート** |

- [ ] 音声トラックが **4本**ある
- [ ] A1・A2 が有効、**A3・A4 がミュート**（Mボタンが点灯 or トラックが無効）
- [ ] A3・A4 の素材が `audio/processed/` 配下のファイルを指している
- [ ] **`raw`側の原音ファイルが書き換えられていない**（更新日時を確認）
- [ ] A1をミュート、A3を有効にして聴き比べができる

補正内容: mic_A は −13.8 LUFS → −14.0 LUFS、mic_B は −14.4 LUFS → −14.0 LUFS に統一済み（ノイズ低減 `afftdn` も適用）。

### 6. マーカーが欠落していないか

| シーケンス | マーカー | 位置 | 種類 |
|---|---|---|---|
| 01_本編 | `[TOPIC] 冒頭` | 0フレーム | 単一点 |
| 01_本編 | `[LAUGH] 笑い（2.0秒）` | 1020〜1080フレーム | **範囲マーカー** |
| 03_short_01 | `[SHORT] 笑いを含む候補` | 0フレーム | 単一点 |

- [ ] マーカーが合計 **3個**（欠落なし）
- [ ] `[LAUGH]` が**範囲マーカー**として入っている（デュレーションを持つ）
- [ ] コメント欄が入っている（`[LAUGH]` には確信度 0.616 が記載されているはず）
- [ ] 接頭辞（`[TOPIC]` `[LAUGH]` `[SHORT]`）が読める
- [ ] マーカーパネルで接頭辞による並べ替え・検索ができるか（色分けの代替として実用に足るかの判断）

### 7. 字幕・チャプター・ショート用データの構造に問題がないか

```
字幕/subtitle.srt     3キュー
字幕/speaker.srt      6キュー
字幕/emphasis.srt     1キュー
youtube-chapters.txt  3行（00:00 から始まる）
```

- [ ] SRT 3本をそれぞれ `ファイル > 読み込み` → タイムラインにドラッグ
- [ ] キャプショントラックとして乗る（キュー数が上記と一致）
- [ ] `subtitle.srt` に**フィラー「えー」が含まれていない**
- [ ] `subtitle.srt` に**句読点（、。）が含まれていない**
- [ ] `speaker.srt` の話者名が2行（名前＋肩書き）で表示される
- [ ] Essential Graphics でスタイルを1回適用すればトラック全体に反映されるか
- [ ] `03_short_01_笑いを含む候補` が **1080×1920**、**361フレーム**（約12秒）

### 8. 日本語・空白を含むパスが正常に扱えるか

素材は `検証素材 fixture/`（**日本語＋空白**）に置いてあります。

- [ ] 再リンクを求められない（項目2と同じ）
- [ ] プロジェクトパネルの素材名が文字化けしていない
- [ ] **可能であれば、フォルダごと外付けSSDにコピーしてXMLのパスを書き換えずに開き、挙動を記録**（実素材の運用に直結します）

## 記録のお願い

`docs/measurements/` のテンプレートに、**○×だけでなく以下**を記入してください。

- 実際に必要だった操作数（クリック・キー操作・ドラッグを1操作として）
- 期待値と違った箇所の**具体的な数値**（例: cam_A のイン点が36ではなく0だった）
- Premiereのバージョン
- 警告・エラーの文言（そのまま）

## 期待値の機械的な突き合わせ

`expected.json` に全期待値が入っています。

```bash
cat ".selfcheck/検証素材 fixture/expected.json"
```

シーケンス名・解像度・フレーム数・クリップ数・音声トラックの有効/無効・マーカーの位置・字幕キュー数がすべて記載されているので、Premiere上の実数と突き合わせれば**欠落率を数値で出せます**。

## この検証で致命的な問題が出た場合

| 症状 | 想定される原因と次の手 |
|---|---|
| XMLが読み込めない | `xmeml` のバージョン（現在5）やDOCTYPE宣言を調整。最小構成（1クリップ1マーカー）まで削って切り分ける |
| 再リンクを求められる | `pathurl` の形式を見直す（`file://localhost` の有無、エンコード方式） |
| マーカーが入らない | マーカー要素の位置（シーケンス直下）を見直す |
| トラックのミュートが効かない | `<enabled>` の要素順を見直す。効かない場合はクリップ単位の `enabled` で代替 |
| イン点がずれる | フレーム換算とNTSC判定を見直す |

**いずれの場合も、EDL経由やUXPプラグインへの方針変更を早期に判断できるよう、症状をできるだけ具体的に記録してください。**
