```bash
npm run selfcheck
```

## この検証で見つかって直した問題

### 1. 同期オフセットの符号（テスト側の誤り）

実装は正しく、テストヘルパーの符号の使い方が逆でした。`offsetSec > 0` の定義を「その素材は基準より**早く録画を開始**した（イン点 = タイムライン時刻 + offsetSec）」とコメントで明示し、`build-project` の規約と一致することをテストで固定しました。

### 2. 笑いの誤検出（実装の問題）★

**通常の会話の被りを笑いと誤判定していました。** 音量変動の「深さ」だけで判定していたため、抑揚のある通常の発話と区別できていませんでした。

対策として、変動の「速さ」（Hz）を併用しました。通常の発話の音節速度は4〜6Hz程度なので、それより上（既定6〜14Hz）を笑いの条件にしています。

さらに、速さの計測で**ヒステリシス（不感帯）**を入れました。エンベロープには必ず細かなリップルが乗るため、単純な符号反転を数えると変動の速さを過大評価します。標準偏差の50%を超える往復だけを1周期として数えるようにしました。

### 3. loudnorm の測定値が取れていなかった（実装の問題）★

ffmpeg の `loudnorm` は測定結果のJSONを **stderr** に出力します。stdout だけを読んでいたため測定値が空になり、**2パス処理と説明していた補正が実質1パス（動的正規化）で動いていました。** stderr も読むように修正し、補正後のファイルが実測で −14.0 LUFS になることを確認しました。

### 4. カメラ切替の検証条件（検証側の誤り）

当初1.5秒の同時発話で引きへの切替を期待していましたが、最短ショット長2.5秒に吸収されるのが正しい挙動でした。フラッシュカットを防ぐルールが働いた結果です。検証用の同時発話を3.5秒に延ばし、意味のある条件にしました。

## この検証で分かっていないこと

**合成素材で確認できるのはパイプラインの接続と算術の正しさだけです。** 以下は実素材でしか確認できません。

| 項目 | 理由 |
|---|---|
| **Premiereでの読み込み**（実測項目1〜10） | XMLの解釈はPremiere本体でしか確認できない |
| 笑い検出の閾値 | 合成音（正弦波の振幅変調）は本物の笑い声と音響特性が違う。**6〜14Hzという帯域は実素材で調整必須** |
| 話者判定のかぶり耐性 | かぶり量を−14dBと仮定した。実際のピンマイクの値で確認が必要 |
| 文字起こしの精度 | 合成音には言葉が入っていないため未検証 |
| 実尺での処理時間 | 40秒素材での検証。10分素材での実測が必要 |

## 補足：合成素材のXMLでPremiereの読み込みを先に試せます

`検証素材 fixture/selfcheck.fcp7.xml` を Premiere で読み込めば、**実素材を待たずに実測項目1・2・8・10（読み込み可否・自動リンク・エラー率・日本語パス）を先に確認できます。** 素材はダミー映像（グレー）ですが、XMLの構造・パス解決・マーカー・トラック構成は実素材と同じ形式です。
