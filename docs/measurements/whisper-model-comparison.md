# 文字起こし（faster-whisper）の検証記録

- 日付: 2026-07-30
- faster-whisper 1.2.1 / ctranslate2 4.8.1
- 環境: Apple Silicon / Python 3.9.6（プロジェクト内 `.venv`）
- 検証音声: macOS `say -v Kyoko` で生成した日本語音声（7.5秒）

```
「採用は広告ではなく、正直な自己紹介です。応募数よりも辞退率を見てください。」
```

業務で頻出する用語（**自己紹介 / 辞退率 / 応募数 / 採用**）を含む文を選びました。日本語は同音異義語が多く、ここが精度の分かれ目になるためです。

## 結果：`small` では業務用語を誤認識、`large-v3` で解消

| モデル | 出力 | 判定 |
|---|---|---|
| `small` | 採用は、広告ではなく、正直な**事故紹介**です。応募数よりも、**自体率**を見てください。 | ✗ 2箇所の誤認識 |
| `small` ＋ 語彙プロンプト | 採用は、広告ではなく、正直な**事故紹介**です。応募数よりも、**自体率**を見てください。 | ✗ **改善しなかった** |
| **`large-v3`** | 採用は広告ではなく、正直な**自己紹介**です。応募数よりも**辞退率**を見てください。 | ✅ **完全一致** |

### 語彙プロンプトは効かなかった

`initial_prompt`（「採用ブランディング、自己紹介、辞退率、応募数…」）と `hotwords` を渡しても、`small` の誤認識は直りませんでした。**「用語をヒントで渡せば軽いモデルでも足りる」という当初の想定は外れました。** 精度はモデル選択が主で、プロンプトは補助と考えるのが妥当です。

固有名詞（ゲスト名・企業名）には効く可能性があるため実装は残しますが、**これに依存した設計にはしません。**

### 確信度が誤認識を正しく示していた

`small` の誤認識箇所は、実際に確信度が低く出ていました。

| 語 | 確信度 | 正解 |
|---|---|---|
| 事 | **0.6876** | 自 |
| 自 | **0.7658** | 辞 |

他の語はほぼ0.95以上でした。**確信度の低い語を抜き出せば、誤認識箇所をほぼ言い当てられます。** `lowConfidenceWords()` として実装し、字幕確認画面で「聞き直したほうがよい箇所」として提示します。**自動修正はしません**（誤った自動修正のほうが害が大きいため）。

`large-v3` では確信度0.6未満の語がゼロでした。

## 処理速度と容量

7.5秒の音声、モデルはキャッシュ済み（2回目以降）:

| compute type | 処理時間 |
|---|---|
| **`int8`** | **9.6秒** |
| `float32` | 16.4秒 |

`float16` を指定すると Apple Silicon では非対応で `float32` に自動変換されるため、**`int8` を既定にしました**（約1.7倍速く、精度差は確認できませんでした）。

| モデル | ディスク使用量 |
|---|---|
| `large-v3` | 2.9 GB |
| `small` | 464 MB |

## 決定事項

| 項目 | 設定 | 理由 |
|---|---|---|
| モデル | **`large-v3`** | `small` は業務用語を誤認識する |
| compute type | **`int8`** | Apple Siliconで最速。精度差なし |
| 言語 | `ja` 固定 | 自動判定に任せる必要がない |
| **VAD（無音除去）** | **無効** | ★沈黙・間は作品の一部。文字起こしの都合で時間軸を詰めない |
| `condition_on_previous_text` | 無効 | 長尺で誤りが連鎖するのを防ぐ |
| 語彙プロンプト | 渡すが依存しない | 実測で効果を確認できなかった |

## 未検証の項目

| 項目 | 内容 |
|---|---|
| **実尺での処理時間** | 7.5秒で9.6秒（約1.3倍の実時間）。10分素材なら**13分前後**の見込みだが未実測。[11.8の見積り（5〜10分）を上回る可能性がある** |
| 実際の会話音声での精度 | TTS音声は発話が明瞭。実際の対談（言い直し・かぶり・早口）での精度は未確認 |
| 話者ごとのマイク音声での精度 | かぶりがある音声で文字起こしの精度が落ちるかは未確認。引き映像の音声と、話者別マイクのどちらを入力にすべきかは実素材で比較する |

**処理時間が想定を超える可能性を明示しておきます。** 実素材で13分以上かかる場合は、(1) `medium` との精度比較、(2) 話者ごとに並列実行、(3) 初回だけ `small` で下書きして確認、の順で検討します。

## 導入手順

```bash
python3 -m venv .venv
.venv/bin/pip install faster-whisper
```

初回実行時に `large-v3`（約3GB）が `~/.cache/huggingface/` にダウンロードされます。**素材を待つ間に一度実行しておくと、実素材での検証時にダウンロード待ちが発生しません。**

```bash
.venv/bin/python scripts/transcribe.py <音声ファイル> --model large-v3 --compute-type int8
```
