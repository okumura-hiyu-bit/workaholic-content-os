# 3. 費用設計 — 固定費0円で始める

## 3.1 原則

> **MVPの目的は市場検証です。固定費は0円。有料サービスは「無料では実現できない」と実証されてから導入します。**

この原則に従い、**月額固定費 0円**で全機能が動く構成に組み直しました。有料の選択肢は、それが必要になる条件と一緒に「Phase2の提案」として分離しています。

## 3.3 前回設計からの変更点（0円化のために）

### ① 音声・動画の置き場：Cloudflare R2 → **GitHub Releases**

前回R2を推奨しましたが、**R2は無料枠内でもアカウントにクレジットカード登録が必要**です。「固定費0円・カード登録なしで始める」というMVPの方針に対して、これは不要な障壁です。

| | GitHub Releases（MVP採用） | Cloudflare R2（Phase2の選択肢） |
|---|---|---|
| 費用 | 0円 | 0円（10GBまで）だが**カード登録必須** |
| ファイルサイズ上限 | 2GB/ファイル | 実質無制限 |
| 転送量 | 無制限・無料 | 無制限・無料 |
| 公開範囲 | **公開リポジトリが必要** | 非公開可 |
| 独自ドメイン | ✗ | ○ |

**「公開リポジトリが必要」は、ポッドキャストにおいては問題になりません。** MP3はそもそも全世界に配信するファイルだからです。**メディア専用の公開リポジトリを1つ作り、コードは別の非公開リポジトリに置く**構成にします。

```
workaholic-content-os          （非公開）… コード・設計・レポート
workaholic-podcast-media       （公開）  … MP3のみを置くリリース置き場
```

RSSに書くURLは `https://github.com/…/releases/download/ep012/ep012.mp3` になります。ここにOP3プレフィックスを付けて計測します。

> **Phase2でR2に移す条件**: 独自ドメイン（`media.workaholic.co.jp`）でMP3を配信したくなったとき、またはクライアント案件で非公開配信が必要になったとき。**その時点でもコストは0円のまま**で、変わるのはURLだけです。`packages/media/storage.ts` の実装を差し替えるだけで移行できるよう抽象化しておきます。ただし**移行時はRSSのenclosure URLが変わる**ため、OP3プレフィックスを最初から挟んでおくことが重要です（プレフィックスが同じなら、リスナー側から見たURLは変わりません）。

### ② AI：Claude API → **Gemini 無料枠を既定に**

前回はClaude API（月100〜300円）を推奨しましたが、**MVPでは Google Gemini の無料枠を既定**とします。月300円は小さい額ですが、「成果が確認できてから有料を導入する」という方針を、最初の1件から徹底するほうが判断がぶれません。

`packages/ai/client.ts` で抽象化し、**環境変数1つで切り替えられる**ようにします。

```
AI_PROVIDER=gemini    # MVP既定・0円
AI_PROVIDER=claude    # 生成品質に不満が出たら切り替え（月100〜300円）
```

**Claudeに切り替える判断基準**（Phase2の提案として明記）:
- 生成文の修正率が3か月経っても50%を超えている（＝AI生成が実質的に時短になっていない）
- 日本語の文体・敬語のニュアンス調整に毎回手間がかかっている
- 月次レポートの分析文が「それらしいだけで中身がない」

これらが観測されたら、月300円で解決するなら即座に切り替える価値があります。逆に、Geminiで十分なら払う理由はありません。**この判断を3か月後にデータで行えるよう、修正率を記録する仕組み**（`ai_original` 列との差分）を最初から入れておきます。

### ③ 文字起こし：ローカルの faster-whisper を使用

クラウドの文字起こしAPIは従量課金です。**手元のMacで `faster-whisper` を動かせば0円**で、30分の音声が数分で処理できます。文字起こしはAI生成の品質を大きく左右する入力なので、ここをケチらずに済むのは重要です。

## 3.4 ポッドキャスト配信が0円で成立する理由

ご指摘のとおり、有料ホスティング（月1,500〜3,000円）は使いません。**構成上、必要ないからです。**

| ポッドキャストホスティングが提供するもの | 本構成での代替 | 費用 |
|---|---|---|
| MP3の保管・配信 | GitHub Releases | 0円 |
| RSSフィードの生成 | Cloudflare Workers（動的生成） | 0円 |
| 各サービスへの配信 | RSSを1回登録するだけ | 0円 |
| ダウンロード分析 | OP3（IAB 2.0準拠） | 0円 |
| 予約公開 | Workerがフィード出力時に時刻で絞る | 0円 |
| 管理画面 | 自作の管理画面に統合 | 0円 |

**有料ホスティングを検討すべき条件（Phase2）**: 動的広告挿入（ダイナミック広告）、有料購読（Apple Podcasts Subscriptions）、複数番組の一括管理が必要になったとき。**いずれも収益化フェーズの機能**であり、市場検証段階では不要です。

## 3.5 GitHub Actions の無料枠を超えない設計

非公開リポジトリの無料枠は月2,000分。実行回数を意図的に絞ります。

| ワークフロー | 頻度 | 1回 | 月間 |
|---|---|---|---|
| SNS投稿実行 | 1日4回（7/12/18/21時 JST） | 約2分 | 240分 |
| KPI取得（SNS + OP3） | 1日1回 | 約2分 | 60分 |
| 週次分析 | 週1回 | 約1分 | 4分 |
| 月次レポート | 月1回 | 約2分 | 2分 |
| **合計** | | | **約306分**（枠の15%） |

ポッドキャストの公開はRSSの動的生成で行うため、**cronを一切消費しません**（[09](./09-podcast.md) 9.4）。

## 3.6 将来、費用が発生しうる箇所（Phase2の判断材料）

現時点では**導入しません**。判断できる状態になってから検討する項目として記録します。

| きっかけ | 費用 | 判断基準 |
|---|---|---|
| AI生成の品質が不足 | Claude API 月100〜300円 | 修正率50%超が3か月継続したら |
| 独自ドメインでMP3配信したい | R2（0円だがカード登録要） | ブランド上必要と判断したら |
| Xへの本格対応 | X API 月100ドル前後 | **費用対効果が最も低い。当面対応しない** |
| クライアント案件の受注 | Meta App Review（無料・2〜4週間） | 受注が決まってから。費用より時間がボトルネック |
| 動的広告・有料購読 | 有料ホスティング 月1,500円〜 | 収益化の目処が立ってから |
| GitHub Actions 超過 | 従量課金 | 3.5の設計を維持すれば発生しない |

**現時点で「有料にすべき」と判断できるものは1つもありません。** 全機能が無料枠で動きます。

## 3.7 市場検証で見るべき数字

固定費が0円なので、**損益分岐点は「かけた時間」だけ**です。MVPの成否は次の指標で判断します。

| 検証項目 | 測り方 | 判断の目安 |
|---|---|---|
| **作業時間が実際に減ったか** | 1本あたりの投稿準備時間 | 従来比で半分以下 |
| **AI生成が使えるか** | 修正率（`ai_original` との差分） | 50%未満 |
| **どの媒体が自社に合うか** | 媒体別の成績 | 3か月で判断 |
| **どの切り口が効くか** | `angle` 別の成績 | 勝ちパターンが1〜2個見つかるか |
| **音声と動画のどちらが効くか** | DL数 vs 再生数、問い合わせ経路 | どちらに寄せるかの判断材料 |
| **問い合わせにつながるか** | 問い合わせ数と流入元 | ★最終的な事業判断の指標 |

これらが取れる状態を作ることがMVPのゴールであり、**きれいな管理画面を作ることではありません。** 実装範囲もこの基準で切っています（[08](./08-mvp-and-steps.md)）。
