# 13. 確認画面MVP と Electron構成

## 13.0 位置づけ

> **これは映像編集ソフトではありません。AIの提案を確認・修正する場所です。**

実装しないもの（ご指示のとおり）: 複雑な編集タイムライン / トランジション / カラー調整 / エフェクト / 音声ミキシング / キーフレーム操作 / ブラウザ上での完成動画編集。

最終的な演出・テンポ調整・細かな編集は Premiere で行います。

## 13.1 レイヤー分離（最重要）

```
┌─ analysis（解析レイヤー）──────────────────────┐
│  ローカル処理の出力。★再解析で丸ごと差し替わる      │
│  文字起こし / 話者 / 字幕 / マーカー /             │
│  カメラ切替案 / チャプター / ショート候補           │
└───────────────────────────────────────────┘
┌─ ai（AI評価レイヤー）─────────────────────────┐
│  APIの出力。解析にも修正にも書き込まない            │
│  順位 / 採用理由 / タイトル案 / 概要欄 / 投稿文     │
└───────────────────────────────────────────┘
┌─ edits（人間修正レイヤー）★絶対に上書きしない ────┐
│  字幕の直し / 話者の付け替え / カメラの差し替え /    │
│  カットの追加・削除 / チャプター名 / 採否 / 履歴     │
└───────────────────────────────────────────┘
                    ↓ resolveProject()
              画面に表示する「実際の値」
```

**`resolveProject(analysis, edits)`** が3レイヤーを突き合わせます（[resolve.ts](../packages/core/src/resolve.ts)）。解析レイヤーも修正レイヤーも書き換えない純粋関数です。

### 再解析で修正が消えない仕組み

修正はIDで紐づきますが、再解析で時刻が数フレームずれるとIDが変わります。そこで2段で照合します。

```
1. IDが完全一致するものに適用（優先）
2. 一致しなければ、IDから読み取った時刻に最も近い要素へ再接続（既定±0.5秒）
3. どちらでも繋がらなかった修正は ★捨てずに orphaned として返す
```

**3が重要です。** 黙って落とすと、編集者は自分の修正が消えたことに気づけません。GUIでは再解析後に必ず次を表示します。

```
⚠️ 再解析の結果、3件の修正の接続先が変わりました
   ・字幕「正直な自己紹介です」→ 0.2秒後ろにずれた箇所へ再接続しました
⚠️ 1件の修正は接続先が見つかりませんでした（内容は保持しています）
   ・ショート候補 short_01 の採用判断 … 候補の区間が変わりました  [内容を見る] [破棄]
```

IDは時刻から決定的に作ります（`sub-00003500` = 3.5秒開始）。同じ時刻なら常に同じIDになるため、解析が安定していれば再接続すら発生しません。

**低confidence語は赤字で強調し、左の一覧から該当位置へ移動できます。** 実測で、誤認識した語は確信度が低く出ることを確認済みです（[記録](./measurements/whisper-model-comparison.md)）。**自動修正はしません。**

**プレビューは「音声のみ」または「低解像度」**です。4Kマルチカメラを扱うため、Electron内で高解像度を再生すると重くなります。低解像度プロキシは ffmpeg で別途生成します（Premiereのプロキシとは別）。

### 依存の向き（★一方向に保つ）

```
apps/desktop  ─┐
                ├→ packages/pipeline → packages/{editing,media,ai} → packages/core
cli           ─┘
```

- `packages/*` は Electron・React・DOM を一切 import しません
- UIは `packages/pipeline` の関数を呼ぶだけ
- **同じ処理をCLIからも実行できる**（`npm run selfcheck` が既にその形）

### プロセス分離

| 処理 | 実行場所 | 理由 |
|---|---|---|
| 解析（ffmpeg・whisper） | **子プロセス** | 数分かかる。メインプロセスを塞ぐとUIが固まる |
| 進捗通知 | IPC（メイン→レンダラー） | ステップ単位で `StepState` を送る |
| ファイル読み書き | メインプロセス | レンダラーに `fs` を渡さない（`nodeIntegration: false`） |
| APIキー | `safeStorage` | OSのキーチェーンで暗号化。★JSONにもコードにも保存しない |

### セキュリティ設定（Electronの既定を守る）

```
nodeIntegration: false
contextIsolation: true
sandbox: true
```

レンダラーには `contextBridge` で必要な関数だけを公開します。`fs` や `child_process` をそのまま渡しません。

## 13.4 APIに送るものの上限（設計上の約束）

| 送る | 送らない |
|---|---|
| ショート候補16本の文字起こし抜粋（各200〜600字） | ★文字起こし全文 |
| 章タイトル・要点・重要発言（ローカルで抽出） | ★映像・音声ファイル |
| テーマ・出演者名 | 素材のパス |

**ショート候補の順位付けで送るのは約3,000〜5,000字**です。10分の対談の全文（約6,000〜8,000字）を毎回送るのと比べて、コストと情報の露出をどちらも抑えられます。

`estimateInputTokens()` が実行前に推定し、確認ダイアログに出します（[cost.ts](../packages/ai/src/cost.ts)）。

## 13.5 実装の順序

Premiere検証で致命的な問題がないことを確認してから着手します。

1. `packages/pipeline` — 解析手順のオーケストレーション（CLIから先に動かす）
2. Electron + React の骨組み、IPC、`nodeIntegration: false` の確認
3. プロジェクト一覧・素材登録（ffprobe連携・役割の推測）
4. 解析進捗（子プロセス＋進捗通知）
5. **確認画面**（字幕・低confidence・カメラ切替・ショート候補の採否）
6. 書き出し画面
7. AI設定（ローカルモードのみで動作確認 → Geminiプロバイダー実装）

**5が最も価値の高い画面**なので、1〜4は最小限で通し、5に時間を使います。
